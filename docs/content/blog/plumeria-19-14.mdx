Plumeria v19.14 moves two more decisions the stylesheet used to make by source order into the lint, so they are reported while the code is written rather than discovered in the browser.

## 1. Conditions that cross

Two conditions that can match at the same time, where neither contains the other, leave the winner to the order they are written:

```ts
const styles = css.create({
  box: {
    '@media (min-width: 600px) and (max-width: 900px)': { color: 'red' },
    '@media (min-width: 700px) and (max-width: 1000px)': { color: 'blue' },
  },
});
```

Between 700px and 900px both queries apply, and nothing ranks one above the other. `no-order-dependent-overlap` now reports such a pair when both set the same property, for `@media` and `@container` alike. Split the ranges so they no longer overlap, or give the overlap a condition of its own.

The rule reports only what it can prove. Two ranges that only touch, such as `max-width: 600px` against `min-width: 600px`, are left alone, and so are conditions with different units or media types. A pair where one condition contains the other is still reported when the narrower one is written first.

## 2. Breakpoints from `createStatic`

`no-order-dependent-overlap` used to read only keys written as strings, so breakpoints kept in `createStatic` went unchecked. It now resolves those keys, including breakpoints imported from another module:

```ts
// breakpoints.ts
export const bp = css.createStatic({
  medium: '@media (min-width: 600px) and (max-width: 900px)',
  wide: '@media (min-width: 700px) and (max-width: 1000px)',
});

// card.styles.ts
import { bp } from './breakpoints';

export const card = css.create({
  box: {
    [bp.medium]: { color: 'red' },
    [bp.wide]: { color: 'blue' },
  },
});
```

The crossing pair above is reported, and so is a narrower breakpoint written before a broader one it falls inside.

## 3. `no-mutable-binding`

The build reads a style definition once, with the values its bindings start with. A `let` or `var` can be reassigned later, but the stylesheet never sees the new value:

```ts
let gap = 8;

const styles = css.create({
  box: { gap },
});

gap = 16;
```

`no-mutable-binding` reports a `let` or `var` binding used in `css.create`, `createStatic`, `createTheme`, `keyframes` or `viewTransition`, and asks for `const`. It is enabled by `recommended` as a warning. The parameters of a dynamic style are untouched:

```ts
const styles = css.create({
  box: (gap: number) => ({ gap }),
});
```

The lint that runs in the build stops on warnings, so a project that declares a style value with `let` sees the build stop until the binding is a `const`.

## Release notes

## 19.14.4 (Oct 18, 2026)

- Fix: `next dev` no longer fails with Module not found after Plumeria is upgraded or downgraded while `.next` is kept, because the Turbopack loaders receive the installed loader version and discard transforms cached by another version

## 19.14.3 (Oct 15, 2026)

- Fix: `next dev` no longer shows a frame without styles when a client component or a style module it imports is edited, because the edited module carries the stylesheet until the updated one arrives

## 19.14.2 (Oct 14, 2026)

- Fix: `next dev` keeps one more previous generation of rules, so a rule is not dropped when edits arrive before every module has updated
- Fix: `compileCSS` no longer fails when a file is deleted while the project is being compiled, such as during a branch switch

## 19.14.1 (Oct 14, 2026)

- Fix: In a project that lints with oxlint only, `init` adds the plugin and its recommended rules to `.oxlintrc.json` instead of writing an `eslint.config` file, and shows the entries to add by hand when the file has comments

## 19.14.0 (Oct 12, 2026)

- Feat: `no-order-dependent-overlap` reports two media or container queries that cross without either containing the other, such as `600px` to `900px` against `700px` to `1000px`, when both set the same property
- Feat: `no-order-dependent-overlap` resolves keys from `createStatic`, including breakpoints imported from another module
- Feat: `no-mutable-binding` reports a `let` or `var` binding used in `css.create`, `createStatic`, `createTheme`, `keyframes` or `viewTransition`, since the build reads only the value it starts with
- Update: README.md
- Fix: Place attribute selectors before pseudo-classes in compound keys recommended by `no-order-dependent-overlap` so they pass `validate-pseudos`.
